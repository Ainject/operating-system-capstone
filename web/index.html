1 · Scheduling

Meet your processes

Each row is a job. Arrival is when it shows up, burst is how long it needs, and priority is how important it is — 1 is the most important. The page numbers are what it asks memory for later.

What does “waiting time” actually mean?

It's how long a job sat in the queue doing nothing, waiting for its turn. Shorter is kinder. Turnaround is the whole trip — from arriving to finishing. Response is how long until it first got a turn.

2 · Memory & paging

What stays on the desk?

Memory is a small desk — it can only hold a few pages at once. When a job asks for a page that isn't there, that's a page fault: the computer has to go fetch it from disk, which is slow. When it's already there, that's a hit — nice and fast.

What does “page replacement” mean, in plain words?

When the desk is full and a new page arrives, something has to leave. FIFO throws out the oldest page. LRU throws out the one you haven't touched for the longest. Optimal cheats — it peeks into the future. That's why Optimal always wins, but a real computer can't do it.

The classic example with 3 frames gives FIFO 15 faults, LRU 12, Optimal 9. Change the numbers and see why.

3 · Combined run

Now put it all together

First we decide who runs, then each job asks memory for its pages while it runs. SJF with 4 frames gets some nice hits. Round Robin with 3 frames is a mess — everyone keeps pushing each other off the desk, so almost every ask is a fault. That's called thrashing, and it feels exactly as bad as it sounds.
